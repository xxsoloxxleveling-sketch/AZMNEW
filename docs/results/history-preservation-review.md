# Examination history preservation: review handoff

This draft changes a reset so the prior attempt, attendance and roster remain associated with the original session. It stores linked legacy scores in an append-only history table and clears the current legacy score fields. Reopening continues to preserve the same attempt and its marks. Deletion of examination history is explicitly unavailable in the API and UI.

Already-owned legacy scores on noncurrent attempts are moved to history by the migration. Unowned scores are left for explicit evidence review; an owned score referencing a missing attempt blocks the migration. Historical legacy scores are available only through a Super Admin, no-store endpoint and the examination history view. The result snapshot is linked to its original session and, for control operations, an immutable operation receipt.

Official Results/DMC records now require an explicit, irreversible, audited Super Admin association to a frozen candidate roster and attempt. The roster establishes that the student participated; it does not prove that the selected attempt corresponds to the result's examination. The administrator must check and attest the examination-specific evidence before binding. No date, class, score or paper version is used to guess this link. Unbound results remain unverified, block reset for the affected candidate, and cannot be verified, published, corrected or used for DMC issuance. A previously issued DMC without the new snapshot association becomes unavailable for download or public verification until its handling is reviewed; binding alone does not rewrite an immutable old snapshot.

After a verified association, reset preserves the old result and issued snapshot against their original attempt, and a separate result can be bound to the new attempt. Historical result and response edits are denied by database triggers as well as the API; DMC revocation remains an append-only event. The UI labels results current or historical. DMC PDFs identify the attempt at issuance. Result creation, correction and reset share the same advisory lock. Synthetic restricted-runtime tests cover wrong-roster and forged-signature rejection, append-only bindings, reset, direct historical edit denial and historical DMC download. Independent review of the explicit attestation, legacy DMC handling, concurrent operations and SQL permissions is still required.

The history and attempt-binding migrations replace existing owned functions, add RLS policies and install triggers on existing Results and response tables. A restricted migrator needs an explicitly controlled owner handoff for those tables and functions, column-level Student update, references, migration-ledger access and reconciliation of the capability-owner grants. A disposable PostgreSQL 17 test rehearses both exact Prisma migrations with synthetic ownership transfer and restoration, including comparisons of pre-existing attendance, roster, audit and finance records; production authorization, backup recovery and independent review remain required. During cutover, dependent operations must be quiesced while ownership changes.

Local synthetic validation includes the examination-control database and browser workflows, restricted-runtime privilege tests, migration-role rehearsal, Results/DMC lifecycle and focused Results tests. No production database, student record, result or service was changed. The draft must remain unmerged and undeployed until CI, independent review and the coordinated release gates pass.
